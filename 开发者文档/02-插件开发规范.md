# 插件开发规范(v2)

插件 = plugins\ 下的一个文件夹: manifest.json + index.js(可带 vendor/、面板、页面)。

## manifest.json

```json
{
  "id": "my-plugin",
  "name": "我的插件",
  "version": "1.0.0",
  "author": "DKXfox",
  "description": "一句话说明",
  "api": "2.0.0",
  "permissions": {
    "network": ["api.example.com"],
    "filesystem": { "read": [], "write": [] },
    "process": false,
    "ports": []
  },
  "ai": { "tasks": ["translate", "chat"] },
  "dependencies": {},
  "conflicts": [],
  "exclusive": [],
  "loadOrder": 100
}
```

- 文件夹名必须等于 manifest.id, 否则跳过(保留 id "security" 不可用)。
- api 必须是 2.x; network 是域名白名单("*" = 任意); process=true 高危(授权弹窗红字 + 需输入插件名确认)。
- ai.tasks 声明插件要用 AI 能力(translate/chat), 经 ctx.ai 调用; 不声明则调用即拒绝。
- 授权哈希 = id@version|api|sha256(index.js): **改版本号或改代码都会使已装用户的授权失效**, 需重新红窗一次。
- 文件读写默认沙盒到自身插件目录与 plugins/<id>/data/; 敏感文件(config.json/*.bak/dev-dongle 等)永拒。

## index.js

```js
module.exports = function (ctx) {
  let timer = null;
  return {
    apply() { ctx.events.on('player.joined', onJoin); },
    dispose() { ctx.events.off('player.joined', onJoin); if (timer) clearInterval(timer); },
    api: { myMethod: async function (input) { /* 控制台可调用 */ } },
    importRows: function (rows) { /* Excel 导入入口(可选) */ },
    panel: { title: '设置', html: function (cfg) { return '...'; } },
    page: { html: function () { return '<html>...</html>'; } }
  };
};
```

ctx 能力: config(持久化设置)/ events.on/off('player.joined'|'player.left', fn) / events.every(ms,fn)→取消函数 / chatbox.send(text,{priority,ttlMs,force}) / chatbox.showSequence(chunks,{priority,eachMs,loops}) / http.request(走 network 门禁 + 插件安全策略) / fs.read|write(沙盒 + 硬拒名单) / exec.run(process 门禁 + 策略) / ai.chat({task,text,lang})(主体代理, 复用用户 AI 配置与三层防线, 每插件 5 秒节流, 密钥不可见) / registerSource({id,priority,intervalMs,getText}) / plugins / logger。
所有经 ctx 的敏感调用写入 logs\plugin-audit.log 审计; 插件直接 require 危险内置模块(child_process/http/https/net/dgram/tls)也会被审计钩子记录。

## 四个必踩的坑(官方全部踩过)

1. **call 传参**: 控制台调用插件接口时, args 对象整体作为唯一参数传入。方法入口先解包: `if (input && typeof input === 'object' && input.input) input = input.input;`
2. **模块级 ctx**: 严格模式下工厂里 `ctx = c` 未声明会 ReferenceError。模块顶部 `let ctx = null;` 再赋值, 或全用闭包。
3. **settings 断引用**: ctx.config 是引用; 运行中改配置必须原地合并(运行时已保证); 重启后 config.plugins[id] 自动回填。
4. **Node 里用 xlsx**: 浏览器版 xlsx.full.min.js 在 Node 会炸; 用 CJS 版(vendor/xlsx.js + vendor/dist/)——参考 friend-welcome。

## 官方示例

- plugins/friend-welcome — 事件 + 面板 + Excel 导入导出 + 控制台内编辑 + 进房快照跳过(1.3.0)
- plugins/scheduled-board — 定时发公告, 最简单完整示例

## 安全模型

非沙箱, 是"契约 + 门禁 + 告知 + 策略": 权限清单声明 → 安装/更新时红色弹窗 + 5 秒倒计时(高危权限需输入插件名)→ 运行时越权抛错并记审计 → 冲突引擎(API 版本/依赖/互斥/同名/优先级)提示。

插件安全策略(plugins.security, 控制台插件卡 0 级可看可**单向收紧**, 放宽需一级密码):
| 键 | 默认 | 可选(收紧方向) |
| --- | --- | --- |
| networkPolicy | whitelist(声明域名放行) | localOnly(仅本机) → off(全禁) |
| processPolicy | consent(审批制) | deny(全禁, 含直接 require child_process) |
| fsWritePolicy | sandbox(仅自身目录+data) | declared(加声明路径) → deny |
| fsReadPolicy | self(仅自身目录) | declared → deny |
| aiPolicy | allow(声明+防线) | localOnly(仅本机 AI) → off |

硬拒名单(config.json / *.bak / dev-dongle / src / scripts / logs / dist 等)对所有策略生效。插件可读写本机文件/发网络请求, 只装可信来源; 诚实边界: 本机有文件写权限者可改代码绕过, 本体系防"被动提取与越权调用", 不防本机所有者。
