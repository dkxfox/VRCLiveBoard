# 冲突检测测试插件(开发自测夹具)

> 这三个目录**永不随包出厂**: `scripts/pack-exclude.json` 排除 + `make-dist.ps1` 按名字跳过 + `pack-audit` 有一条 `^conflict-test` 禁入正则兜底。只在开发机与你自己的实例里出现。

| 目录 | 作用 | 声明的权限 |
| --- | --- | --- |
| `conflict-test` | 主夹具: 审批窗 + 冲突 + **权限自测** | 网络 `example.com` / `api.github.com`、写文件、**进程**、端口 `19191`、**AI(`translate`/`chat`)** |
| `conflict-test-b` | 伙伴: 与主夹具共享独占资源 + 同优先级数据源 | 无 |
| `conflict-test-dep` | 演示"启用被拦": 缺依赖 + 与 `weather-board` 互斥 | 无 |

## 怎么试(约 5 分钟)

1. **刷新插件列表**: 控制台 → 插件 → 「重新扫描」(或重启程序)。三个都会出现在列表里。
2. **看审批窗**: 打开 `conflict-test` 的开关(未授权会弹红窗)。
   期望: 权限逐项列出(网络两个域名 / 写文件 / **进程执行=红字** / 端口 19191 / **AI 能力 translate,chat**);
   因为同时有 `process` 与 `ai`, 它属于**高危档** —— 底部必须**输入插件名或插件 ID**(`冲突检测测试(全权限)` 或 `conflict-test`)才能批准, 按钮还有 5 秒倒计时。
   (插件卡顶部的「插件AI」下拉里也应该能看到它 —— 这一条正是 1.4.5 修的那个缺口。)
3. **看冲突(两条)**: 批准并启用 `conflict-test`, 再启用 `conflict-test-b`。两张卡上应出现:
   - `独占资源冲突: vrchat-chatbox`(两边声明了同一个独占资源)
   - `聊天框显示优先级相同,内容会互相抢占`(两个数据源优先级都是 45)
4. **看"启用被拦"**: 批准 `conflict-test-dep`(批准没问题), 然后点启用。
   期望: **启不起来**, 提示 `冲突: 缺少依赖插件 no-such-plugin(要求 >=1.0.0)`(或 `与 weather-board 互斥`)。这是冲突引擎的设计行为, 不是故障。
5. **测权限(全权限那个)**: 在 `conflict-test` 卡片里调用它的 `selfTest` 接口(控制台 → 插件 → 该插件的调用入口)。
   期望逐项:
   - ① 网络 `example.com` → 允许(离线时会报失败原因)
   - ② 写自己目录 → 允许;③ 读回 → 允许(写的是 `plugins/conflict-test/data/selftest.txt`, 已加 .gitignore)
   - ④ 写 `config.json` → **被拒(硬拒名单)** —— **这一条要是没被拦住, 请立刻告诉我**(那就是真漏洞)
   - ⑤ 进程 → 允许(会在 `logs/plugin-audit.log` 留一条审计)
   - ⑥ AI(`ctx.ai`) → 允许(需先在高级设置里配好 AI 接口; 没配会给出明确原因)
6. **(可选)看策略热生效**: 高级设置 → 安全与权限 → 把「进程执行」改成 `deny`、「插件AI」改成 `off`, 再点一次 `selfTest`: ⑤⑥ 应立即变成"被拒", 不用重启。
7. **(可选)看端口声明**: 夹具声明了 19191 但**不会真的监听** —— 想验证"声明了也不等于能监听", 看审批窗里的端口条目即可。

## 想换冲突条件?

直接编辑对应目录的 `manifest.json`, 再「重新扫描」:

- `dependencies: {"某插件 id": "版本"}` → 缺依赖 / 版本不符 → **启用被拦**
- `conflicts: ["某插件 id"]` → 声明互斥 → **启用被拦**
- `exclusive: ["资源名"]` → 独占资源: 另一个插件声明同名资源即报冲突(**不拦启用**)
- `api: "3.0.0"` → 会报「插件要求 API 3.0.0,当前运行时为 2.x」(同时该插件会加载失败 —— 属预期)
- `permissions` 想加什么加什么: 审批窗会照实列出来(改权限会让已装用户重新走一次红窗)

## 收尾

试完可以: 停用 → 删除(插件卡片里的删除按钮, 可恢复), 或直接留在 `plugins/` 里反复用。它们不会进任何发布包。
