# 02 · 社区协议(仅本地自用参考)

> ⚠️ 这一路是**对非公开接口的逆向使用**, 随产品分发有明确法律风险(见 `04-合规与风险.md`)。
> 本文件只作为"你自己本机玩"与"理解官方协议帧结构"的参考, **不要**做成随包分发的功能。

## 帧结构(16 字节头)
| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 4 | 整包长度(大端) |
| 4 | 2 | 头长度(通常 16) |
| 6 | 2 | 协议版本 protover |
| 8 | 4 | 操作码 op |
| 12 | 4 | 序号 sequence |

- `protover`: 0/1 = 纯 JSON; 2 = zlib 压缩; 3 = **brotli** 压缩(官方现在多用 3);
- `op`: 2 = 心跳(客户端发, 一般 30s 一次) / 3 = 心跳回应(人气值就在这里) / 5 = 普通消息(业务 CMD) / 7 = 认证 / 8 = 认证回应;
- 认证包 body 里带 `uid` / `roomid` / `protover` / `platform` / `buvid` 等字段。

## 连接入口
1. 先拿直播间信息(`room/v1/Room/get_info`)确认房间号;
2. 再取弹幕服务器地址(`xlive/web-room/v1/index/getDanmuInfo`);
3. 默认服务器参考: `broadcastlv.chat.bilibili.com` (wss 443 / ws 2244 / tcp 2243)。

## 登录态
- 匿名可连; 但 **2023 年 7 月之后, 完整用户名需要登录态(Cookie)**;
- → 如果产品要"显示观众名字", 就必须碰用户账号凭据 —— 这是**最贵的一项成本**(不是流量, 是信任)。

## 消息类型(CMD)速查
| CMD | 含义 |
| --- | --- |
| `DANMU_MSG` | 实时弹幕(`info[1]`=文本, `info[2][0]`=uid, `info[2][1]`=用户名) |
| `SEND_GIFT` / `COMBO_SEND` | 礼物 / 礼物连击(`giftName`, `num`, `coin_type`: silver/gold) |
| `SUPER_CHAT_MESSAGE` | 醒目留言(`price`, `message`, `time` 展示时长, 背景色) |
| `GUARD_BUY` / `USER_TOAST_MSG` | 上舰长/提督/总督 |
| `INTERACT_WORD` | 进房/关注/分享等互动 |
| `WELCOME` / `WELCOME_GUARD` | 欢迎老爷 / 舰长 |
| `ROOM_REAL_TIME_MESSAGE_UPDATE` | 房间实时数据(粉丝数、点赞等) |
| `WATCHED_CHANGE` | 看过人数变化 |
| `ONLINE_RANK_COUNT` / `ONLINE_RANK_V2` | 高能榜/在线榜 |
| `LIKE_INFO_V3_UPDATE` 等 | 点赞数变化 |
| `ROOM_BLOCK_MSG` / `ROOM_KICKOUT` 等 | 管理类事件 |

## 现成实现(参考实现思路, 不直接依赖)
- Python: [`blivedm`](https://github.com/xfgryujk/blivedm) —— **同时支持网页端与官方开放平台两种接口**, 对照读很有价值;
- Node/TS: [`blive-message-listener`](https://github.com/ddiu8081/blive-message-listener)(底层 `tiny-bilibili-ws`, 类型友好);
- 指令字段清单: [`BiliLiveCmds`](https://github.com/xuan25/BiliLiveCmds);
- 协议分析文章: [B站直播弹幕ws协议分析](https://cloud.tencent.com.cn/developer/article/2218972)、[BiliBili直播弹幕WS协议浅析](https://cloud.tencent.cn/developer/article/2378808)。

## 工程注意
- 心跳按契约发(约 30s), 断线**指数退避**重连;
- 别高频轮询 HTTP 接口(同 IP 容易被风控);
- 收到 `-352` 之类错误码 = 被风控, 要能识别并退让, 不要死循环重试。
