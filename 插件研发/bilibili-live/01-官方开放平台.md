# 01 · 官方直播开放平台(推荐路线)

## 站点
- 开放平台首页: https://open-live.bilibili.com/
- 直播&互玩接入文档: https://open-live.bilibili.com/document/bdb1a8e5-a675-5bfe-41a9-7a7163f75dbf (接入指引)
- 「互玩」/互动玩法中心: https://play-live.bilibili.com/ (你在直播里看到的"互动小游戏"就挂在这一类能力上)
- 开发者入驻说明: https://bilibili.apifox.cn/doc-885661

## 门槛(已核实)
第三方接入实录的原话: **"B站审核较宽松, 只要申请就能通过, 没有特殊条件, 只要实名认证可以进行任何操作"**
(来源: 接入bilibili直播开放平台 · 时光潜流 —— https://cloud.tencent.com.cn/developer/article/2200010)
→ 结论: **不需要企业资质, 实名认证即可**。这是"给所有人用"时选官方的前提条件。

## 接入流程(三步)
1. 实名账号入驻 → 创建项目 → 拿 `app_id` / `access_key`;
2. 主播侧授权/绑定直播间(实录里 `/v2/app/start` 的入参含 `code` + `app_id`; `code` 与主播绑定有关 —— 具体形式以官方文档为准);
3. 调 `start` 拿长连接地址与认证体 → 连 wss → 按官方要求**定时保活**。

## 端点(从跑通的实现里核到)
```
POST https://live-open.biliapi.com/v2/app/start       # 开启长连接会话, 返回 wss 地址与认证信息
POST https://live-open.biliapi.com/v2/app/heartbeat   # 心跳保活(不按时上报会掉线)
POST https://live-open.biliapi.com/v2/app/end         # 结束会话
```
- 签名: **Hmac-SHA256**; 长连接: WebSocket + 心跳保活;
- 消息帧结构与社区协议同源(16 字节头 + op 码, 见 `02-社区协议.md` 的帧结构一节, 那部分是共通的)。

## 能拿到什么
- 事件推送: 弹幕 / 礼物 / 醒目留言(SC) / 上舰 / 点赞 / 进房等(与 `02` 表格里的 CMD 对应);
- 具体是否包含**人气/在线/看过**这类房间数据 → **未确认**(官方文档站是 JS 渲染, 抓不到正文)。

## ⚠️ 待确认三问(申请时顺便问清楚)
1. 官方是否提供**人气 / 在线 / 看过人数**数据? 若没有, 我们是否接受"少这几个指标"?
2. 主播端**授权绑定**的具体流程与限制: 是每个主播各绑一次吗? 有数量/时效限制吗?
3. 是否有**调用量 / 并发 / 费用**限制? 断了怎么重连?
