# 10 · 抢占 / 排队 / 防丢 / 聚合 策略(用户 2026-09-20 拍板)

> 实现落在 `lib/policy.js`(纯函数) + `lib/policy.test.js`(**20 条断言全绿**)。
> 机制依据: `src/composer.js` —— `pushTransient(text, priority, ttlMs, force)` 压入临时文本,
> 每秒 tick 把"数据源快照 + 所有临时文本"按优先级降序取第一条发送; 同优先级时数据源在前(让路);
> 临时文本过期后数据源自然赢回来(所以不需要我们自己恢复); `composer.current` 暴露当前来源/优先级/剩余时长。

## 一、四条需求 → 落地规则
| 需求(用户原话) | 规则 |
| --- | --- |
| "增加一个选项中断其它功能数据" | `preemptBackground`(默认**开**): 开启时, 弹幕**抢占**后台数据源(公告板 5 / 电脑状态 10 / 歌曲 30); 关闭时一律排队 |
| "手动触发才有用的功能比如截图翻译和翻译系统可以不忽略" | **两条保护**: ① 当前显示来自 `livetranslate`(语音字幕)或 `ocrregion`(截图区域) → 一律让路; ② 当前显示优先级 ≥ `respectPriority`(默认 **85**, 覆盖截图翻译 85 与插件欢迎 90) → 一律让路。这期间的消息**排队** |
| "SC弹幕和礼物上舰信息…信息防丢, 防止其他功能占用时触发被顶掉" | 三类事件标记为**高价值**: 排队时**不设时效**(等到能显示为止), 出队时**优先于普通弹幕**, 上限 50 条, 只有超过上限才丢最旧**并记日志** |
| "重复类型的弹幕可以自动压缩, 很多人同时发 666 就显示 666×123" | **聚合窗口**(默认 5 秒): 同一文本首次出现**立刻显示原文**, 窗口内其余重复**压住不刷屏**, 窗口结束时若累计 >1 就补一条 **`文本×N`**(格式可配, 默认 `{text}×{n}`) |

## 二、决策表(当前显示 → 弹幕怎么办)
| 当前显示 | 来源/优先级 | 弹幕(75) |
| --- | --- | --- |
| 空场 | — | 立刻显示 |
| 公告板 | `pages` / 5 | **抢占** |
| 电脑状态 | `hardware` / 10 | **抢占** |
| 歌曲 | `media` / 30 | **抢占** |
| 语音字幕 | `livetranslate` / 40 | **让路 + 排队**(来源保护, 与优先级无关) |
| 截图区域 | `ocrregion` / 45 | **让路 + 排队**(来源保护) |
| 截图翻译结果 | transient / 85 | **让路 + 排队**(优先级地板) |
| 插件欢迎 | transient / 90 | **让路 + 排队**(优先级地板) |
]

## 四、队列与时效
| 类 | 队列上限 | 时效 | 超出怎么办 |
| --- | --- | --- | --- |
| 普通弹幕 | 20 | **30 秒**(弹幕有时效性) | 超时/超限都丢最旧, 且**记日志**(丢弃必须可见) |
| 高价值(SC/礼物/上舰) | 50 | **不设** | 只有超上限才丢, 并记日志 |

## 五、聚合细节
- 键 = **完全一致**的文本(先不做相似度归一化 —— `666` 与 `6666` 算两条; 要不要归一化等你看到真实弹幕再定);
- 首次出现立刻显示: 观众能马上看到有人说话;
- 窗口内不刷新计数(避免聊天框跳数刷屏); 窗口结束补一条 `666×123`;
- 冲刷条件: 距该文本**最后一次**出现超过窗口时长;
- 格式可配: `{text}` / `{n}`, 默认 `666×123`。

## 六、新增配置字段(`plugins['bilibili-live']`)
| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `preemptBackground` | `true` | 是否允许中断其它功能数据 |
| `respectPriority` | `85` | 当前显示优先级 ≥ 此值一律让路 |
| `protectSources` | `['livetranslate','ocrregion']` | 永不打断的来源 |
| `sourcePriority` | `{}` | 逐类事件优先级覆盖, 如 `{ "GIFT": 82 }` |
| `danmakuQueueTtlMs` | `30000` | 普通弹幕排队时效 |
| `queueMax` | `20` | 普通队列上限 |
| `highValueQueueMax` | `50` | 高价值队列上限 |
| `aggregateWindowMs` | `5000` | 重复弹幕聚合窗口 |
| `aggregateFormat` | `'{text}×{n}'` | 聚合显示格式 |

## 七、已知限制(诚实记录)
1. **composer 没有"移除已压入的临时文本"的 API** → 聚合靠"窗口内不压"实现, 而不是改旧条目(所以是"首次原文 + 窗口后计数"两条, 不是实时跳数);
2. 高价值排队的最长等待 = 当前显示剩余时长(例如截图翻译结果 15 秒), 不会更久;
3. **队列只在内存里**(不落盘 —— 与项目"不采集、不落库"的口径一致): 程序重启期间的事件会丢, 这是**有意取舍**;
4. 硬规则"优先级 ≥85 一律让路"是刻意的: 手动结果优先。想让弹幕反过来抢, 把 `respectPriority` 调低即可。
