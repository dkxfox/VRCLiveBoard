# B站直播互动 —— 开发资料(代码已搬走)

> 2026-09-20: **代码已搬进 `plugins/bilibili-live/`**(插件的唯一源, 见 GPLUG 门禁"单一源"规则),
> 本目录只留**调研资料与设计记录**, 整个 `插件研发/` 都不进发布包。
> 插件源码: `plugins/bilibili-live/`(`index.js` + `lib/六个模块` + `test/离线单测`);自检命令 `node plugins/bilibili-live/test/run-all.js`。

## 一句话结论
- **给所有人用 → 走官方直播开放平台**(实名认证即可申请, 审核宽松; 社区协议属于"逆向非公开接口", 随产品分发有明确法律风险)。
- **想两条路都留 → 共享上层、隔离下层**: 玩法层只认统一事件模型; 官方 adapter 进包, 社区 adapter 只在本机(pack-exclude 排除, 不发布)。
- **体积不是问题, 但别引第三方库**: 自实现约 600~900 行 / 30~50KB, 用 Node 内置 `WebSocket` + `zlib`(含 brotli) + `crypto`(Hmac) + `fetch`, **零新增依赖**。

## 代码结构(在 plugins/bilibili-live/)
| 模块 | 职责 | 断言 |
| --- | --- | --- |
| `lib/frame.js` | 帧编解码: 16 字节头 + zlib/brotli 递归展开 + 半包 | 11 |

## 开发路线(2026-09-20 起)
0. **已拿到**: `access_key_id` / `access_key_secret`(申请通过邮件);
1. **已拿到**: `app_id`(已创建互玩项目, **值只在本机**)与 `room_owner_auth_code`(幻星「身份码」);
2. **已完成**: 帧解析 → 显示策略 → 签名与请求构造 → 双心跳/重连 → CMD 事件模型 → 事件→聊天框桥(共 **166 条离线断言**);
3. **进行中**: 插件搬进 `plugins/bilibili-live/` + 真 API 接线(`ctx.chatbox` / `ctx.events` / `ctx.http`)→ 控制台设置面板(四个参数掩码 + 测试连接);
4. **待用户**: 在控制台启用插件、填四个参数、点「测试连接」, 然后开播验证头顶弹幕;
5. **之后**: 按 `05` 的玩法优先级扩展(礼物触发 OSC 动作 / 上舰播报 / SC 醒目展示)。

## 顺带记下的小坑(与本插件相关的既有问题)
- `package.json` 写的是 `engines.node >= 18`, 但插件用了**全局 `WebSocket`**(需 Node 21+/22) —— Node 18/20 用户启用本插件会看到明确的报错提示; 建议把 engines 提到 `>=22`。
- 控制台的「打开页面」按钮(第三方面板)在当前版本是**死按键** —— `index.html` 里没有 `plgPanelOverlay`/`plgPanelFrame` 容器, 面板路由仍只回 JSON; 本插件的设置改为走"插件卡片里的设置字段"(见 `docs/ISSUES.md`)。
