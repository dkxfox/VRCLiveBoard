# B站直播互动插件(占位) + 调研资料

> 建档 2026-09-20。**本目录不是可用的插件**, 是"占位置 + 存资料"用: 先把结论、接口、风险与玩法整理好,
> 过些天再回来开发。README 只做导航, 细节看 01~06。

## 一句话结论
- **给所有人用 → 走官方直播开放平台**(实名认证即可申请, 审核宽松; 社区协议属于"逆向非公开接口", 随产品分发有明确法律风险)。
- **想两条路都留 → 共享上层、隔离下层**: 玩法层只认统一事件模型; 官方 adapter 进包, 社区 adapter 只在你本机(pack-exclude 排除, 不发布)。
- **体积不是问题, 但别引第三方库**: 自实现约 600~900 行 / 30~50KB, 用 Node 内置 `WebSocket` + `zlib`(含 brotli) + `crypto`(Hmac) + `fetch`, **零新增依赖**。

## 当前状态
- `manifest.json`: 合法(api 2.0.0, 只声明官方通道需要的三个域名), 拷进 `plugins/` 能正常加载、不报错;
- `index.js`: 空的 `onLoad/onUnload`, 什么都不做 —— 占位用;
- 本目录**不进发布包**(已登记 `scripts/pack-exclude.json`), 也不会被插件管理器扫描(它只扫 `plugins/`)。

## 回来开发时的第一步
1. 读 `01` 与 `04`, 决定路线(建议官方优先);
2. 按 `01` 的"待确认三问"去 [open-live.bilibili.com](https://open-live.bilibili.com/) 申请项目, 拿到 `app_id` / `access_key`;
3. 读 `05`, 先落**事件模型 + official adapter 接口位**(不连真环境也能写, 用本地夹具测帧解析);
4. 最后接 UI(申请向导 + 测试连接)与公告板变量。

## 顺带记下的小坑(与本插件相关的既有问题)
- `package.json` 写的是 `engines.node >= 18`, 但项目里已有代码用**全局 `WebSocket`**(歌词插件 `cdp.js`) —— 它要 Node **21+ / 22 才稳定**。
  也就是说 Node 18/20 用户跑歌词插件会失败。建议把 engines 提到 `>=22`(本机是 Node 24), 而不是引入 `ws` 依赖。
