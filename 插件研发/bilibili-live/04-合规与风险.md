# 04 · 合规与风险(决策依据)

> 这不是法律意见, 是"照平台自己的公开表态做事"的工程判断。

## 平台法务函点名的四件事(第三方库 bilibili-api 被永久关停)
该仓库 README 现在挂着 B 站委托律所的侵权告知函, 明确点名四类行为:
1. 对**非公开接口 / 认证体系 / 访问控制机制**做逆向分析与适配;
2. **突破登录态与访问控制、绕过反爬风控与签名鉴权**;
3. 抓取付费内容(番剧/课程);
4. **采集弹幕并反查用户真实身份**。

## 最要命的一句(与"插件发给所有人"直接相关)
告知函里的措辞包括: **"将针对平台的爬取能力作为官方特性内置、持续更新、随每一次版本发布向不特定用户分发"**
→ 这正是"做一个插件、随软件发给所有用户"的形态。

## 结论(已与用户讨论 2026-09-20)
- **给所有人用 → 官方开放平台**(有授权、有文档、有契约);
- **社区协议 → 仅本机自用, 不进发布包、不发布**(可做开发者本地插件);
- 两条路都想要时的正确做法: **共享上层玩法、隔离下层传输** —— 用户拿到的包里只有官方 adapter。

## 产品级红线(无论走哪条路都别踩)
1. **不碰登录态**: 不让用户填账号密码/Cookie 到产品里(官方通道也不需要);
2. **不采集身份信息**: 弹幕里的 uid / 昵称 / 头像 → 只在内存里用于当场显示, **不落库、不外传**;
3. **不做批量监听**: 只连用户自己配置的直播间;
4. **不做数据造假/刷量**: 不提供任何"刷人气/刷弹幕"能力;
5. **不绕过风控**: 遇到 `-352` 等风控返回就退让, 不做重试绕过;
6. **频率要礼貌**: 心跳按契约、HTTP 轮询 ≥10s、断线指数退避。

## 分发形态的差异(风险不是一个量级)
| 形态 | 风险 |
| --- | --- |
| 你本机自用(不发布) | 低 |
| 随插件市场/发布包分发给不特定用户 | **高**(上面那句被告知函点名) |
| 作为"官方特性"内置并持续更新 | **最高** |
