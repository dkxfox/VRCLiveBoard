# F-20261014-01 插件动作桥(控制台点按钮调用插件方法)

> 状态: DRAFT -> 待用户过七问后进 D1。来源:2026-10-14 做「相机运镜控制」插件时发现
> `docs/PLUGIN-DEV.md` 早已记录该缺口:「面板路由只回 JSON, **没有"面板内函数 → 插件 api 方法"的桥**」。

## 0. 状态
- 状态: DRAFT
- 归属: **主体**(插件系统基础设施, 非某个插件专属)
- 目标版本: 1.5「月光」/ 或紧随其后的补丁版
- 关联: `plugins/camera-path`(第一个使用方)

## 1. 七问(D0)

1. **谁在什么场景下用**:
   装插件的用户, 在控制台的插件卡上**点一个按钮**, 让插件做一件事(例: 「播放选中的运镜」「停止」)。
   目前插件只能靠"设置项 + 轮询"这种土办法触发 —— 本卡把这条路修成正道。

2. **要不要占聊天框**: **不占**。纯控制台交互, 与聊天框无关。

3. **新配置项**: **不新增主体配置键**。声明写在各插件自己的 manifest 里:
   ```json
   "actions": [{ "name": "playDolly", "label": "播放选中的运镜", "hint": "延迟 3 秒后播放" }]
   ```
   公开版行为: 未声明 actions 的插件不受任何影响(向后兼容)。

4. **新端点**: `POST /api/plugins/action` -> `{ ok, result }`;
   错误码: 400(参数缺失/未知 action) · 403(action 未在 manifest 声明) · 404(插件不存在或未启用) · 500(插件方法抛错);
   门禁级别 = **一级**(本机可用; 控制器仍需先通过"插件启用"这道门)。

5. **新依赖**: **无**。

6. **失败降级**:
   - 插件未启用 / 无该方法 -> 返回明确错误, **前端按钮置灰并标注原因**(不静默);
   - 插件方法抛错 -> 捕获后 500 + 错误摘要, 前端提示"插件报错: …";
   - 旧版插件(无 actions 声明) -> 卡片不渲染按钮区, 一切照旧。

7. **不做什么**:
   - ✗ **不做任意方法调用**(只允许 manifest 里**声明过**的 action 名 —— 这是本卡的安全底线);
   - ✗ 不做参数表单(第一版只做无参按钮; 需要参数时放进插件自己的设置里);
   - ✗ 不做插件间调用(那是另一件事);
   - ✗ 不做 streaming/长任务(按钮调用必须**快速返回**, 长任务让插件自己异步 + 用状态回显)。

## 2. 待确认(A0 歧义闸)
- "点按钮"是否需要**二次确认**?建议: 默认不需要(动作幂等/可撤销), 若 action 声明里带 `"confirm": true` 才弹确认。

## 3. 四契约(D1 预告, 待七问确认后填实)
- **API**: `POST /api/plugins/action`(白名单 + 结构化错误);
- **配置**: 无主体新键; manifest 新增可选字段 `actions`;
- **显示**: 插件卡新增"动作区"(按钮 + 结果回显 + 置灰理由);
- **权限**: 沿用现有插件权限体系; action **不绕过**权限(插件自己受沙箱约束)。
