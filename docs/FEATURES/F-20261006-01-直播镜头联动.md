> 状态: **DRAFT**(等用户过 D0 七问)。流程见 `docs/PROCESS-02-开发更新.md`, 调研依据见 `docs/CAMERA-OSC-RESEARCH.md`。
> 起因: 用户 2026-10-05 的想法 —— "相机运镜 + 直播插件 + 动作控制, 很有节目效果"。

## 1. 七问(D0)

1. **谁在什么场景下用**:
   开 VRChat 直播的人。**收到醒目留言/上舰/礼物时, 镜头自动做一段运镜**(推到公告板前 / 环绕 / 切预设机位), 弹幕刷屏时切无人机视角。
   一句话: **把"导播切镜头"这件事自动化, 由直播事件触发。**

2. **要不要占聊天框**: **不占**。优先级 = 不参与, 显示时长 = 不适用, 与任何源都不冲突(本功能只发 OSC, 不写聊天框)。

3. **新配置项**: `plugins.live-camera` 段(插件自己的配置, 不新增主体配置键); 公开版默认**关闭**(需要 VRC+ 与相机 OSC, 不能默认开)。安全开关: 默认只允许**本机** OSC 目标。

4. **新端点**: **不新增主体路由**(插件通过自身的插件配置页与主体 OSC 发送能力工作); 若必须暴露状态, 用插件卡展示, 门禁级别 = 零级。

5. **新依赖**: **无**(纯 OSC 报文 + 现有发送链路)。若后续要读 Camera Dolly 轨迹文件, 也只读 VRChat 自己的目录, 不引第三方库。

6. **失败降级**:
   相机 OSC 端点不存在 / 用户没有 VRC+ → **静默降级**: 不再发相机报文, 插件卡上显示"相机 OSC 不可用", 其余直播功能(弹幕/礼物进聊天框)**完全不受影响**;
   发送失败 → 记一条诊断, 连续失败 N 次后自动停用本插件并提示。

7. **不做什么**(非目标):
   - ✗ 不做相机画面采集/推流(那是 OBS 的活);
   - ✗ 不做"控制别人的镜头"(OSC 是本地能力);
   - ✗ 不做 UI 内的运镜编辑器(先只做"预设机位 + 事件触发");
   - ✗ 不碰 VR 覆盖层(那是另一条线, 见 `docs/VR-OVERLAY-NOTES.md`);
   - ✗ 不在未验证端点清单前承诺"能自由移动相机"。

## 2. 待验证(切片 0, 未验证不许进设计)

**这是本功能能否成立的前提, 必须先用最小代价验掉:**

1. ⚠️ `/usercamera/` 的**完整地址清单**(官方 OSC 文档相机章节) —— 重点是**有没有位姿/运动类端点**;
2. ⚠️ 已确认可写的三个动作端点是否真能用: 给 `/usercamera/Capture` 发一条, 看相机是否**拍照**;
3. ⚠️ **Camera Dolly 的轨迹**能否被外部读写(用户提到可导出/导入 —— 若能通过文件交换, "预设机位"就能做成配置);
4. ⚠️ Camera Drone 的"适用于 OSC"具体指哪些地址。

**验证方式**: 只发 OSC、不改本体(**调研状态**, 见 PROCESS-05 §7.1); 或复制副本做实验。
**验证通过后才进 D1 四契约。**

## 3. 为什么这条路比 VR 覆盖层简单(2026-10-06 结论)

| | 直播镜头联动(本卡) | VR 覆盖层(`scripts/vrkeyboard` 暂停中) |
| --- | --- | --- |
| 技术栈 | **纯 OSC**(项目已有) | 需**新增原生组件**(C#/.NET + D3D11 + SteamVR 输入清单 + 7 种手柄绑定) |
| 复用现有能力 | 直播插件已在解析弹幕/礼物/上舰 | 无, 要从零起步 |
| 风险 | 端点能力未确认(切片 0) | 三个死结曾是暂停原因, 样本证明可行但仍重 |
| 规模 | 小(一个插件) | 大(接近一次 1.5 级别的大更新) |
| 结论 | **先做这个** | 留给 1.5 之后, 按笔记 §3 四步最小验证重启 |
