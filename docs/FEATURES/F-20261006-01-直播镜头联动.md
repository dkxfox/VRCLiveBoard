# F-20261006-01 直播镜头联动(相机 + 直播事件 + 动作)

> 状态: **DRAFT**(等用户过 D0 七问)。流程见 `docs/PROCESS-02-开发更新.md`, 调研依据见 `docs/CAMERA-OSC-RESEARCH.md`。
> 起因: 用户 2026-10-05 的想法 —— "相机运镜 + 直播插件 + 动作控制, 很有节目效果"。

## 0. 状态

- 状态: DRAFT

- 目标版本: 插件 0.1.0(随 1.5「月光」, 或先做实验版)

## 1. 七问(D0)

1. **谁在什么场景下用**:
   开 VRChat 直播的人。**收到醒目留言/上舰/礼物时, 镜头自动做一段运镜**(推到公告板前 / 环绕 / 切预设机位), 弹幕刷屏时切无人机视角。
   一句话: **把"导播切镜头"这件事自动化, 由直播事件触发。**

2. **要不要占聊天框**: **不占**。优先级 = 不参与, 显示时长 = 不适用, 与任何源都不冲突(本功能只发 OSC, 不写聊天框)。

3. **新配置项**: `plugins.live-camera` 段(插件自己的配置, 不新增主体配置键); 公开版默认**关闭**(需要 VRC+ 与相机 OSC, 不能默认开)。安全开关: 默认只允许**本机** OSC 目标。

4. **新端点**: **不新增主体路由**(插件通过自身的插件配置页与主体 OSC 发送能力工作); 若必须暴露状态, 用插件卡展示, 门禁级别 = 零级。

5. **新依赖**: **无**(纯 OSC 报文 + 现有发送链路)。若后续要读 Camera Dolly 轨迹文件, 也只读 VRChat 自己的目录, 不引第三方库。

6. **失败降级**:
   相机 OSC 端点不存在 / 用户没有 VRC+ → **静默降级**: 不再发相机报文, 插件卡上显示"相机 OSC 不可用", 其余直播功能(弹幕/礼物进聊天框)**完全不受影响**;
   发送失败 → 记一条诊断, 连续失败 N 次后自动停用本插件并提示。

7. **不做什么**(非目标):
   - ✗ 不做相机画面采集/推流(那是 OBS 的活);
   - ✗ 不做"控制别人的镜头"(OSC 是本地能力);
   - ✗ 不做 UI 内的运镜编辑器(先只做"预设机位 + 事件触发");
   - ✗ 不碰 VR 覆盖层(那是另一条线, 见 `docs/VR-OVERLAY-NOTES.md`);
   - ✗ 不在未验证端点清单前承诺"能自由移动相机"。

## 2. 待验证(切片 0, 未验证不许进设计)

**这是本功能能否成立的前提, 必须先用最小代价验掉:**

1. ⚠️ `/usercamera/` 的**完整地址清单**(官方 OSC 文档相机章节) —— 重点是**有没有位姿/运动类端点**;
2. ⚠️ 已确认可写的三个动作端点是否真能用: 给 `/usercamera/Capture` 发一条, 看相机是否**拍照**;
3. ⚠️ **Camera Dolly 的轨迹**能否被外部读写(用户提到可导出/导入 —— 若能通过文件交换, "预设机位"就能做成配置);
4. ⚠️ Camera Drone 的"适用于 OSC"具体指哪些地址。

**验证方式**: 只发 OSC、不改本体(**调研状态**, 见 PROCESS-05 §7.1); 或复制副本做实验。
**验证通过后才进 D1 四契约。**

## 3. 为什么这条路比 VR 覆盖层简单(2026-10-06 结论)

| | 直播镜头联动(本卡) | VR 覆盖层(`scripts/vrkeyboard` 暂停中) |
| --- | --- | --- |
| 技术栈 | **纯 OSC**(项目已有) | 需**新增原生组件**(C#/.NET + D3D11 + SteamVR 输入清单 + 7 种手柄绑定) |
| 复用现有能力 | 直播插件已在解析弹幕/礼物/上舰 | 无, 要从零起步 |
| 风险 | 端点能力未确认(切片 0) | 三个死结曾是暂停原因, 样本证明可行但仍重 |
| 规模 | 小(一个插件) | 大(接近一次 1.5 级别的大更新) |
| 结论 | **先做这个** | 留给 1.5 之后, 按笔记 §3 四步最小验证重启 |

## 6. 我建议补充的(请你裁一下)

> 按 D0 "不答完不许进设计" 的规矩, 下面每条都要么进范围、要么明确写进"不做什么"。

### 6.1 必须补进前提的(不确认就没法设计)
1. ⚠️ **VRChat 自带运镜的导出文件格式未知** —— 这条是需求 3 的命门:
   格式若可解析 -> 导入可行;若是私有/加密格式 -> 需求 3 只能做"导出给我们自己"。
   **切片 0 必须先验这个**(找到文件、看格式、试着解析);
2. ⚠️ **OSC 有没有"位姿/连续运动"端点** —— 这条决定"播放轨迹"能不能做:
   只有拍照类端点 -> 只能做**离散切机位**;有位姿端点 -> 才谈得上**沿轨迹播放**(且要考虑刷新率, 20~60Hz 的 OSC 流是否吃得消);
3. ⚠️ **VRChat 是否回传相机位姿** —— 决定"录制运镜"能不能做(已知 LookAtMe 偏移是回传的, 位姿未确认)。

### 6.2 我建议补进范围的
4. ⭐ **"录制运镜"**(把当前操作录成预设) —— 导入/导出之外的自然补充, 也是**没有 VRC+ 用户**也能用的入口;
5. ⭐ **触发冲突规则**(需求 5 的必要配套): 同时来两个事件(上舰 + 礼物)谁赢?
   建议照搬主体已有的优先级思路: **事件分级 + 高优先级打断 + 同级排队 + 超时丢弃**;
6. ⭐ **降级必须显式可见**: 没有 VRC+ / 端点不存在时, 插件卡上明确写"相机 OSC 不可用",
   而不是静默失败(否则用户以为坏了);
7. ⭐ **VR 里的触发方式要说清楚**: 键盘快捷键在 VR 里按不到(手柄没有 F 键)——
   建议触发口做成三种: **桌面快捷键 + OSC 触发(Stream Deck/外部程序可用) + 控制台网页按钮(手机/平板在 VR 里也能点)**;
8. ⭐ **轨迹查看的形式**: 建议先做**俯视二维图 + 速度/朝向曲线 + 时间轴**, 不做三维编辑器(那是另一个量级的活);
9. ⭐ **"联动接口"的安全边界**(需求 2 的必要配套): 外部程序能触发运镜 = 新的本地面;
   建议沿用项目现有的插件权限体系: **只允许本机、默认关闭、需在插件权限里显式声明、可在安全设置里一键停用**;
10. ⭐ **实验功能的开关层级**: 复用现有的**「显示实验性功能」**开关(主体已有 `ui.experimental`, 2026-10-05 刚修好它不落库的问题),
    本插件在关闭时**完全不可见**, 不新增第二个实验开关;
11. ⭐ **和"动作控制"的关系要定死**: 你原始想法是"相机 + 直播 + 动作",
    那么"**一个触发 = 镜头 + avatar 参数 + 聊天框文案**"这种**组合场景**是不是第一版就要?
    建议**第一版先做镜头**, 组合场景作为切片 4(否则一轮做不完)。

### 6.3 建议写进"不做什么"的

- ✗ 不做相机画面采集/推流;
- ✗ 不做"控制别人的镜头";
- ✗ 不碰 VR 覆盖层(那条线独立评估);
- ✗ 未验证端点清单前, 不承诺"能自由移动相机"。

### 6.4 测试怎么做(断言要能自动跑)
- **假 OSC 接收端**: 门禁里起一个本地 UDP 监听, 断言"事件 -> 发出的报文地址/参数"正确;
- **降级断言**: 模拟端点不存在 -> 断言插件停发且状态可见、其余功能不受影响;
- **导入解析断言**: 用**样例文件**跑解析(样例取自 VRC 导出 —— 若格式不可解析, 这条断言本身就会失败, 正好把结论钉死)。
