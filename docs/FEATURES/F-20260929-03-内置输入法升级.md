# F-20260929-03 内置输入法升级: 从"标签机"到"现代输入法"

> 来源: 用户 2026-09-29 —— 「我想把自带的输入法升级一下, 现在打字感觉就是像用标签机那样的简单设备, 一点都不现代化。GitHub 上有没有开源的输入法比较好的。」
> 状态: **切片 1/1b/2/3/4 全部交付(功能闭环); 仅剩可选的切片 5(联想)**。本文给出"可执行选项 + 依据 + 代价"。

## 1. 现状(先承认差距在哪)
当前 `src/pinyin.js` 是**查表式**输入法: 完整拼音 / 前缀 / 简拼三类命中 + 选词学习, 词库 6 万条。
- 它能做的: 逐词打、按词频排候选;
- 它做不到(正是"标签机感"的来源):
  · **整句转换** —— 打 `jintiantianqihenhao` 期望直接出「今天天气很好」, 而不是先选「今天」再选「天气」;
  · **上下文/语言模型** —— 候选只看当前拼音串, 不看前后文;
  · **纠错与模糊音** —— 打错一个字母就查不到(`zh/z`、`an/ang`、`l/n` 等);
  · **联想** —— 上屏后不预测下一个词;
  · **用户词频** —— 只有"学过没有", 没有"用了多少次"。

## 2. GitHub 上的开源输入法(已核对的候选)
| 项目 | 许可 | 语言 | 对我们有什么用 |

## 3. 关键判断: "现代化"的实质不是词库大小, 而是**语言模型**
按"投入产出"排序, 真正让输入法"现代化"的是这四件事:
1. **整句转换(HMM/Viterbi)** ⭐⭐⭐ —— 一次打完一整句, 依据 start/emission/transition 概率找出最可能的汉字序列。**这一条带来的体感提升最大**, 也正是上面那个 MIT 的 JS 库直接提供的;
2. **用户词频** ⭐⭐ —— 记录"用过多少次"并按次数排序(我们已有 `learn` 的雏形, 升级为计数即可);
3. **模糊音与纠错** ⭐⭐ —— `zh/z`、`ch/c`、`sh/s`、`an/ang`、`in/ing`、`l/n`、`f/h`; 打错一两个字母仍能命中;
4. **联想/下一个词** ⭐ —— 上屏后预测下一个词。

## 4. 建议方案(三选一, 我推荐 A)
**A. 只换引擎(推荐)** —— 接入 `pinyin-input-method-engine` 当算法层:
- 我们**保留** `src/pinyin.js` 的对外接口(`GET /api/pinyin`、`POST /api/pinyin/learn`)与现有网页键盘/候选条 UI, **只换内部实现**;
- 好处: 端点契约不变(路由基线不变)、UI 不变、**风险最小**, 而体感提升最大(整句);
- 代价: 新增一个 **MIT 依赖**(需按项目规矩登记到 `docs/THIRD-PARTY.md`); 其自带字典许可与其引用的上游(`Pinyin2Hanzi` 等)也要一并核对, 必要时**用我们的 jieba 词库自己生成**。
**B. 换引擎 + 换 UI** —— 再加 `pinyin-ime` 的 `<pinyin-ime-editor>`:
- 好处: 候选框 UI 直接拿来(9 项/翻页/高亮), 我们少写前端;
- 代价: 我们**已经**有自绘下拉与键盘页 UI, 引入第二套 UI 反而重复; 且它是 Lit 组件, 与现有无框架前端风格不一致。
**C. 只抄设计, 自己写** —— 照 RIME/Google 拼音的思想, 用我们自己的词库手写 HMM:
- 好处: 零外部依赖、许可最干净;
- 代价: 要自己准备 start/emission/transition 概率表(可从 jieba 词频估算), 工作量与调参成本显著高于 A。

## 7. 搜狗词库迁移(用户提问: 「有没有能兼容搜狗词库的, 方便迁移?」)

### 7.1 结论: **能**, 而且有事实标准工具
- **深蓝词库转换 / imewlconverter**(`studyzy/imewlconverter`, **★10.4k**, 今天仍在更新): 支持 **搜狗 / QQ / 百度 / Rime / 微软拼音** 等词库互转, 能读搜狗的导出词库(含二进制用户词库)与自定义短语;
- 另有若干小工具(如 `godcrying/scel2rime`、`caiguanhao/sogoudict` —— 解析 `.scel` 细胞词库)可作备选。

### 7.2 ⚠️ 许可红线(决定了怎么用它)
- imewlconverter 是 **GPL-3.0** ✗ -> 我们**不打包、不链接、不抄它的代码**;
- 正确用法: **它只是一个由用户在自己机器上运行的桌面工具** -> 纯工具使用对我们的许可**零影响**(与"不要引入 GPL 代码"这条规矩不冲突);
- 用户词库/细胞词库本身是**第三方数据** -> 与我们处理 MMD 动作同一条规矩: **只放本地(gitignored), 绝不入库、绝不随包分发**。

### 7.3 迁移路径(四步, 用户只需做前两步)
```
① 搜狗输入法 -> 属性设置 -> 词库 -> 导出用户词库(.bin)  (+ 自定义短语)
② 用深蓝词库转换(用户本地运行)导出为纯文本, 每行形如:  词  拼音  词频
③ 放进用户目录(与 assets/motions 同样的 gitignored 规则)
④ 我们的构建脚本读取它 -> 合并进引擎的 JSON 字典(个人词优先 + 词频提权)
```

### 7.4 对 D0 第 3 问的影响(词库来源)
多出第三条路, 而且是最贴身的一条:
| 选项 | 评价 |
| --- | --- |
| 用第三方库自带的字典 | 省事, 但要核对其上游许可, 且词频与用户习惯无关 |
| 只用我们的 jieba 词库 | 干净, 但"不认识你常打的词" |
| ⭐ **搜狗用户词库 + jieba** | **既有你自己的词汇与词频, 又保持数据本地化**; 与"个人词优先"的语言模型正好互补 |
