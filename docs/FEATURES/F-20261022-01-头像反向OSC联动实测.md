## 4. 结论（可直接用于动作输出层的判断）

1. **反向通道本身是通的**：`/input/*`（动作）与 `/avatar/parameters/VRCEmote`（内置表情）在真实头像上均实测生效 —— 动作输出层的设计与自动复位逻辑可以按原计划推进。
2. **`/avatar/parameters/<Bool>` 用 int 0/1 写入未生效**：至少对 Mamehinata 的 `C_BodyBag` 如此（int 值 0 明确发出、游戏内无变化）。
3. 可能原因（待逐条排除）：
   - Bool 参数在 OSC 里需要 **float 0.0/1.0** 或不同类型标签（部分实现如此）；
   - 需要 VRChat 自带 **OSC Debug** 面板确认「报文到达」与「参数名匹配」；
   - 该头像参数经 VRCFury 构建后实际类型/菜单行为与 OSC 配置表不一致（需要用 OSC Debug 看回读值）；
   - VRChat 版本对 Bool 写入的兼容问题（3.10.x 时代）。
4. **对「外挂式跳舞驱动」的含义**：时间轴/进度类参数应优先用 **Float/Int**（int 已实证 VRCEmote 有效），不要先依赖 Bool 通道。

## 8. 2026-10-30 补充：VRChat 原生 Face Tracking 的 OSC 接口（与本卡的关系）

VRChat **2026.4.1**（2026-10-28 Live）新增原生面捕 OSC；核实结论见 `docs/RESEARCH-FACE-OSC.md`（E3 官方 + E1 本机）：

- **方向一（外部→VRChat，新能力）**：`/tracking/face/v1`，OSC **blob**（类型标签 `b`），**恰好 102 字节**，每字节 0~255 解码为 0~1；102 键顺序见官方 beta 文档。**不是 102 个独立地址**。
- **方向二（VRChat→外部，只有 3 个只读布尔）**：`/avatar/parameters/UserEyeTracking`、`/avatar/parameters/UserFaceTracking`（内置 Animator 参数的默认 OSC 输出映射）、`/avatar/avatarfullfacetracking`（OSCQuery，头像是否支持面捕）；另有新端点 `/avatar/name`。
- **前提**：头像必须在上传时启用 Face Tracking + `Use All Tracking Keys`（制作侧 SDK 仍为 **3.10.6-beta.4**；正式 SDK 尚未支持）。→ 是"不再需要自定义同步参数/prefab"，**不是**"任意头像零改装"。
- **对本卡/动作输出的影响**：以后做"表情驱动"可直接发 102 字节 blob，不必让用户改模型同步参数；但需要 beta SDK 头像；本机当前头像 `avatarfullfacetracking=false`，**驱动效果尚未实机验证**。
- **用户原话核实**："VRC 把自带的面部参数映射到 OSC" —— **基本成立但方向要说明**：是把 102 个 UE 键接成**输入** OSC 端点；不是把 102 个值逐个输出给外部。
