## 1. 关键结论(先说答案)

1. **文本链路我们已经有了, 不需要动核心程序**: 主体已提供 `POST /v1/chatbox`(本地外部程序可直接推文本到聊天框, 与 /api/chatbox 同一处理器), 而聊天框本身走 OSC `/chatbox/input` —— 虚拟键盘只需要"产生文本 → 调这个 HTTP 接口"。
2. **真正缺的只有「在 VR 里显示 + 点按」这一层**, 而它有三种做法(按侵入性排序):
   - **A. 不自己画 overlay(零原生代码, 今天就能用)**: 把键盘做成主体里的一个页面(大按钮 + 中文输入), 用户在 VR 里用**已有的桌面视图**操作 —— SteamVR 自带 Desktop View、Virtual Desktop 的桌面、或用户已装的 OVR Toolkit / XSOverlay。
   - **B. 自研 SteamVR overlay(OpenVR IVROverlay)**: 截图那类工具的做法。需要 SteamVR 运行环境 + 一个**独立原生助手**(C++/C#; 项目里已有 C# launcher 先例)负责"画覆盖层 + 控制器射线当鼠标", 拿到的文本回传主体 HTTP 接口。**主体仍然零改动。**
   - **C. OpenXR overlay(XR_EXTX_overlay)**: 更"标准", 但生态成熟度与运行时覆盖不如 OpenVR(见参考资料), 建议按需再评估。
3. **中文输入有两条路**: ① 键盘页放一个隐藏输入框, 交给 **Windows 系统输入法**(最省事, 但候选窗在 overlay 里不好显示); ② **自带拼音候选**(JS 词库, 完全可控, 但要自己写候选/翻页/联想)—— 截图里那个「中文/英文」按钮说明对方多半走的是 ② 或自带 IME。
4. **144 字上限**与我们一致: VRChat 聊天框就是 144 字, 主体 composer 已有 maxChars=144 的处理, 键盘页做同一个计数器即可。

## 2. 七问(D0, 待用户确认的部分我标了?)

1. **谁在什么场景下用**: VR 里想打一段中文(不便开口/静音/需要留字)时, 不想摘下头显去用屏幕键盘。
2. **要不要占聊天框**: 不占。键盘只是**输入源**; 文本仍走聊天框的既有优先级(默认 80)与限频。
3. **新配置项**: 待定 —— 预计 `vrkeyboard.enabled`(默认 false, 遵守"新功能默认关闭")、`vrkeyboard.sendPriority`、`vrkeyboard.maxChars`(默认 144)、短语表 `vrkeyboard.phrases`、是否记录历史 `vrkeyboard.history`(默认 false, 与"不采集"口径一致)。
4. **新端点**: 复用 `POST /v1/chatbox`; 若要做"历史/短语/候选"再加 `GET/POST /api/vrkeyboard/*`(门禁级别待定, 建议零级但只本机可访问, 与既有 /v1/* 同口径)。
5. **新依赖**: A 方案 **零新增依赖**(纯前端页面); B 方案引入一个原生助手(OpenVR 头文件 + 构建链), **不进主体包**、按需单独分发, 主程序与插件目录都不受影响。
6. **失败降级**: 助手不在/SteamVR 没运行 → 键盘页仍可当普通网页用; 中文输入法不可用 → 退化为英文 + 短语; 发送失败 → 页面上给回执(不静默)。
7. **不做什么**: 不做自动发言/按脚本刷屏(只做人工输入); 不做"注入按键到别的程序"(那是 OVR Toolkit 的地盘, 风险与工作量都更大); 不做 Quest 独立机版本(需要完全不同的显示路径)。

## 3. 覆盖范围与风险(诚实)

- **SteamVR 是唯一"第三方 overlay 成熟"的路径**; Virtual Desktop / Quest Link / 独立机 情况各异(OVR Toolkit 这类工具本身就是跟着 SteamVR 走的, 参考其 Quest 讨论帖), 所以 B 方案只覆盖一部分用户 —— **需要先确认你自己的 VR 环境**。
- 主体侧风险低: 外部程序 + OSC 聊天框都是官方支持通道; 只要保持"人工输入"就不触碰 VRChat 的滥用红线。
- B 方案的真实成本不在"画键盘", 而在: 原生工程的构建/签名/更新链、以及"没装 SteamVR 时优雅降级"。

## 11. 切片 2 增补②: 只保留「我说话时」的转写(2026-09-28)
- 背景: LiveTranslate 路线准确率好, 但会把环境里别的玩家的话一起带进来。
- 做法: 用 VRChat 回传的 `Voice`(麦克风电平)与 `Viseme`(口型)维护"我在说话"的时间窗口 → 只保留时间戳落在窗口内的转写行(±2 秒), 其余丢弃并记日志。
- 边界: 静音时无法判断(那时 VRChat 不上报 Voice/Viseme)→ 不过滤; 与人同时说话可能一起留下; 判据精度到秒。
- 开关: 控制台"只保留我说话时的转写"(默认开)。
- **安全阀(2026-09-28 修)**: 过滤后一行不剩 -> 保留全部; 本次会话从没见过 Voice/Viseme(静音) -> 不过滤。即"宁可混进别人的话, 也不能让用户说完什么都没发"。窗口宽容度: 前 3 秒 / 后 6 秒(LiveTranslate 落盘有延迟)。
- 验收: backend-flow 158 PASS / 0 FAIL(新增"我的一句留下、别人的话被滤掉")。

## 13. **撤回「笔迹 OCR」候选**(2026-09-28, 用户否决) + 流程纠正
- 用户原话(要点): 「笔迹 OCR 没用啊, 直接用游戏世界里的笔或者模型插件上的不就能写了吗 …… 这类玩家时间长了都能站在你面前写镜像字了, 游戏世界里都能直接看见了, 再识别一次有什么意义? …… 翻译系统的 OCR 我早就想砍掉了, 精度太差, 根本识别不了花体字和方块字, 你还指望它能识别在三维空间里变形的手写字? 提意见能不能靠谱点。改程序要按照标准流程来。」
- **撤回结论**:
  · 世界里**本来就能写、能看**(玩家甚至会写镜像字给对方看)→ 「把写好的字再识别一遍」**没有增加任何能力** ✗;

### 16.2 四张契约
- **API 契约**: 插件对外只暴露必要的本机接口 —— `POST /api/plugins/muteness-assist/keyboard`(键盘开/关/布局切换)、`GET` 状态(是否在听/键盘是否在显示/当前布局); **门禁级别: 零级**(只本机可访问, 与 `/v1/*` 同口径)。覆盖层工具 → 文本入库走既有 `POST /v1/chatbox`(不再造第二条链路)。错误码: 400 参数错 / 403 跨站 / 409 覆盖层未运行。
- **配置契约**: `plugins.muteness-assist.{enabled, keyboard:{layout:'full'|'numpad', opacity, scale}, phrases:[...], asr:{enabled, engine, mineOnly}, overlay:{exePath, autoStart}}`; 默认全部**关闭**; `config.default.json` 同步; 老配置缺键由 `main.js` 预建对象兜底(与既有一致)。
- **显示契约**: 优先级 **80**(与"临时推送(HTTP API)"同档; 同档先到先得, 不与 B站礼物 80 互相抢占); `ttlMs 8000`; 144 字符截断沿用 composer; 与"来源保护/当前显示 ≥85"两条硬规则冲突时**一律排队**(既有规则优先)。
- **权限契约(`manifest.permissions`)**: `network`: 仅本机(监听 127.0.0.1 的 OSC/HTTP, 不对外发); `process`: 启动听写助手(仅当用户开语音); `filesystem`: 自己的 `plugins/muteness-assist/data`(短语/历史) + **只读** LiveTranslate 转写目录。**事实提醒**(PROCESS-02 §2): 权限是契约式审计, 真正的信任边界是**红窗授权**; `dgram` 只在 `networkPolicy=off` 时被拦(默认 whitelist 下允许, 但会记 `plugin-audit.log`)。

### 16.3 覆盖层工具的技术选型(有现成先例, 零工具链)
- **C# + Windows 自带 `csc.exe`**: 与现有桌面启动器同一套构建方式(`scripts/launcher/build.bat` 用 `.NET Framework 4.0.30319` 的 csc, **不需 Visual Studio / NuGet**) ✓;
- **OpenVR**: 直接 P/Invoke `openvr_api.dll`(SteamVR 安装目录自带; 若随工具分发需登记 **Valve BSD-3** 到 `THIRD-PARTY.md`); 覆盖层事件流(mouse move/button)按官方 `IVROverlay` 用法;
- **键盘渲染**: GDI+ 离屏位图 → overlay 纹理(项目里已有 GDI+ 截图先例, 复用同一套 GDI+ 经验);
- **内置输入法**: 构建期用 Node(`pinyin-pro` + `@node-rs/jieba`, 均 MIT)生成紧凑"拼音→候选+词频"词库文件, 工具启动时加载; 候选交互按"射线点选"设计(一排 5~7 个大按钮 + 翻页);
- **启动方式**: 随 SteamVR 自启动(与 OVR Toolkit 同法) + 由插件按开关拉起/关闭。
