# F-20260929-05 输入法与主程序多语言联动(简/繁/英)

> 来源: 用户 2026-09-29 —— 「我们的输入法是支持繁体输入的吧? 如果是的话, 我们让他和主程序的多语言联动如何? 简体中文就简中文本优先, 繁中就繁体字优先, 英文就默认不调用中文输入法, 这样在26键盘左下方ZXC这一排隔一个格子加个中英切换和大写, 九键旁边也加个中英切换和大写。符合本地用户输入习惯。」
> 状态: **已交付**(2026-09-29)。

## 1. 繁体: 原本**不支持**, 现在支持了
- 事实: 引擎的词库(DAG 14 万词组 + HMM 概率表)与内置词库(6 万)都只有**简体**数据 -> 候选出来必然是简体;
- 做法: **简->繁 转换**(OpenCC 的 JS 版 `opencc-js`, 许可 **MIT AND Apache-2.0**, 两者都宽松) —— 不动引擎就能拿到繁体, 而且是**词汇级**消歧(面/麵、里/裡);
- 实测: `这个输入法真不错` -> **`這個輸入法真不錯`**; 长句 `我们是一只再做一个有用得工具` -> `我們是一隻再做一個有用得工具`;
- 开销: 首次加载转换器 81ms, 之后 **0ms**; 并且**懒加载** —— 只有界面是繁體时才 require。

## 2. 联动的判定与默认值
| 界面语言 | 行为 |
| --- | --- |
| **简体中文** | 简中候选优先(不转换) |
| **繁體中文** | 候选**转繁体**后再显示 |
| **English** | **默认不调用中文输入法**: 字母直接进聊天框(不打拼音、不出候选) |
- 判定在**请求层**: `GET /api/pinyin?...&lang=zh-TW` -> 服务端按 `^(zh-)?(tw|hant|hk|mo)$` 判断是否转换(**没有新增路由**, 基线不变);
- 客户端的**中英开关**默认跟随界面语言, 并存 localStorage(用户手动切过就听用户的)。

## 3. 两个键的位置(用户指定)
```
26 键:   ...  A S D F G H J K L
              [⇧] Z X C V B N M   [中/EN]     <- 隔开一格
九键:    1 ，   2 abc  3 def  ...  0 空格  # 拼音/数字
              [⇧]  [中/EN]                   <- 键盘正下方
```
- **⇧ 大写**: 打开后字母大写并**直接上屏**(大写字母不是拼音);物理键盘的 Shift 也认(`ev.key` 本身是大写就保留);
- **中/EN**: 显示**当前**状态(中文时显示「中」, 英文时显示「EN」), 打开时有强调色边框。

## 4. 顺带修掉的一个潜在 bug
- 原来的物理键盘监听在焦点位于 `INPUT/TEXTAREA` 时**直接返回** -> 而键盘页现在会把焦点放进聊天框(选完词就聚焦), 于是**物理键盘打字母会被浏览器直接塞进去, 中文输入被绕过**;
- 现在: 焦点在**聊天框**内也接管字母(并 `preventDefault`), 其它输入框/文本域一律不打扰。

## 5. 数据与许可
- 新增运行时依赖 **opencc-js**(MIT AND Apache-2.0), 已登记 `docs/THIRD-PARTY.md`;包体约 6MB(以词典为主), 但**只在繁体界面下才加载**;
- 没有引入任何第三方词库(繁体靠转换, 不靠外部数据)。
