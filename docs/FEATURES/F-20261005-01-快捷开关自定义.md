# F-20261005-01 快捷开关组可自定义

> 来源: 用户 2026-10-05 附图 —— 「我想把这个快捷开关组做成可以自定义的, 编辑模式显示完整的插件和功能列表, 然后用户自己打钩确定是否显示。」
> 状态: **D0/D1 已写, 等用户过目后进 D2**。

## 1. 现状(读代码得到的事实, 比预期完整)
「常用」页那张「功能开关」卡已经有一套雏形:
```
index.html   #switches 卡: 标题(secSwitches) + 提示(switchesHint) + 编辑/保存按钮(#swEditBtn)
app.js       editing 状态: 点按钮 -> 进入编辑模式 -> 每行前面多一个 .swpick 复选框
             打钩 = 显示(勾掉就把 key 放进 hidden 数组)
             保存时 POST /api/config { ui: { dashHide: [...] } }
             读回时 hidden = c.ui.dashHide
```
**也就是说: 打钩=显示 的语义、编辑模式、持久化字段(`ui.dashHide`)都已经有了** ✓

## 2. 真正的缺口(用户要补的就是这一处)
⚠️ 编辑模式只给**当前已经渲染出来的那几行**加复选框 —— 而列表本身是**按启用状态渲染**的:
- 被隐藏/停用的项**不出现在列表里** -> **看不见, 也就永远点不回来** ✗
- 结论: 现在只能"把已显示的关掉", 不能"把没显示的打开" —— 这是个**单向开关**。

## 3. D1 四契约(建议)
| 契约 | 内容 |
| --- | --- |
| **配置契约** | 沿用 `ui.dashHide: [key]`(向后兼容: 老配置照旧生效); 可选新增 `ui.dashOrder: [key]` 用于自定义顺序(**先不做**, 见待确认 3) |
| **API 契约** | **不新增路由** —— 仍走 `GET/POST /api/config`(基线不变) |
| **显示契约** | 编辑模式下: **全量列表**(所有数据源 + 所有插件, 不论启用与否) + 每项一个复选框(默认按 `dashHide` 勾选) + 明确标注"**打钩 = 显示在快捷开关里**"; 非编辑模式: 只渲染勾选的项 |
| **权限契约** | 不适用(不是插件); 但编辑模式里**已停用的插件/数据源也要能勾选显示** —— 显示 ≠ 启用, 两者不联动(避免"勾一下就把插件打开了") |

## 4. 切片(D2)
| 切片 | 内容 |
| --- | --- |
| 1 | 编辑模式改为**全量列表**(数据源 + 插件各一段), 每项带复选框; 未勾选的不渲染 |
| 2 | 空态与数量提示(例如"共 12 项, 显示 7 项")|
| 3 | 保存/取消(取消还原到进入编辑前的勾选)|
| 4 | 断言: 静态(全量来源存在)+ 行为(勾选/取消/持久化/老配置兼容)|

## 5. 待用户确认(D0)
1. **全量列表要不要分段**?(建议: 「数据源」「插件」两段, 每段按名称排序)
2. **已停用的项**要不要也能勾选显示?(建议: 能 —— 显示与启用分开, 否则又会变成单向开关)
3. **要不要支持排序/拖拽**?(建议: **先不做**, 一次只解决"能不能勾回来")
4. 卡片标题/按钮文案: 现在是「功能开关 / 数据源·插件 一键启停 / 编辑→保存」, 要不要改成更直白的「**快捷开关**」+「编辑」?
