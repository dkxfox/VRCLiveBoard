## 1. 技术可行性: 能做与不能做(先说清楚, 免得白做)

### 1.1 **能做的**: 我们当"PC 端播放器"
- VRChat 的模型动作由**模型自带的 Animator + 动画片段**播放, **参数**决定"放哪一段、放到第几秒";
- 外挂程序能做的正是**驱动这些参数**:
  · **时间轴同步**: 每帧把"当前进度"(归一化 0~1 的 float)发给 `/avatar/parameters/<Float>` -> 模型里的接收端按它播放(**这就是各类 dance sync 的工作原理**);
  · **选曲/触发**: 发 `/avatar/parameters/<Int>` 或内置的 **`VRCEmote`**(int 1~8) -> 切歌 / 触发内置舞蹈;
  · 我们现在**已经有**这套发送能力(动作输出层, 已交付并测过)。

### 1.2 **不能做的**(必须提前讲明)
- ❌ **不能把任意 MMD 动作"注进"别人的模型**: VRChat 的动画片段必须**烘焙在模型里**, 运行时无法外部注入 -> 所以「**模型里完全不装任何东西就能跳任意 MMD**」做不到;
- ✅ 但「**不用装第三方 PC 端工具**」做得到: 模型里只需一个**接收参数并播放**的简单 prefab(很多免费/开源方案提供), **PC 端那个难用/收费的播放器由我们替代**;
- ✅ 另一种**纯外挂**情形: 模型里本来就是**固定几支舞**(用 `VRCEmote` 或自定义 int 选曲), 那我们连接收端都不用改, 直接发参数即可。

### 1.3 一个关键精度事实(决定体验)
- VRChat 的 **Expression Parameter** 同步时**每个参数最多 8 bit**(来源: proustite「Float Expression Parameters 同期の概念」: 「パラメータごとに最大 8bit を使用して同期」) -> 远端看到的进度是 **256 级**;
- 而 **OSC 本地设置不受这个限制** -> **本人看到的是平滑的**, 旁人看到的是量化的;
- 对我们的意义: 播放器可以放心地按 **30~60Hz** 发 float, 本地体验由我们的平滑度决定; 远端同步质量取决于模型参数位深(这一点要在功能说明里如实写)。

## 2. 免费的 MMD 动作哪里找(**许可风险必须逐条看**)

| 来源 | 说明 | 许可特点(务必逐条确认) |
| --- | --- | --- |
| **ニコニ・コモンズ**(Niconi Commons) | 日本 MMD 动作/镜头配布的**主阵地**, 有结构化许可标签(商用可否 / 改変可否 / 再配布可否) | 标签清晰但要**逐个看**; 很多作品明确写「MMD 以外での使用禁止」 |
| **Booth** | 大量**免费配布**的动作(也卖付费) | 每个商品页有条款; 免费≠可再配布 |
| **BowlRoll** | 老牌文件中转, 很多早期动作在此 | 许可全凭作者说明, 风险较高 |
| **VPVP wiki / MMD モーション配布 まとめ** | 索引型页面, 用来找作品 | 同上 |
| **YouTube 配布動画** | 视频描述里给下载链接 | 绝大多数是「**MMD 限定**」「**VRChat 使用禁止**」 |
| **Mixamo**(Adobe) | 不是 MMD 风格, 但**为真人模型设计的免费动作库** | 许可**允许用于 VRChat 等作品**, **禁止把动作文件本身再分发** |

### 2.1 ⚠️ 一条会导致法律问题的红线
**绝大多数 MMD 动作禁止"MMD 以外用途"、明确禁止 VRChat、禁止再配布。** 因此:
- ✅ **我们的插件绝不能内置/附带任何动作文件**;
- ✅ 正确架构: **插件只做"播放器 + 参数发送"**, 动作文件由**用户自备**(他自己确认过许可的 VMD/FBX);
- ✅ 插件里可以放**示例配置与说明**(怎么把自己的动作挂进来), 但不放素材本身。

## 3. 与现有能力的衔接(复用什么)
- **动作输出层**(`src/actions.js`, 已交付): 轴/按钮自动复位 + 限速 + `resetAll` -> 我们**新加**的"参数流"发送要沿用同一套安全约束(速率上限、断开时归零);
- **触发器层**(`src/triggers.js`, 已交付): 手势 -> 开始/停止跳(用户此前已拍板触发要可自定义);
- **直播插件预研**: 本功能真正要预研的是"**时间轴 -> 定时/高频 OSC 流**"这套机制 —— 直播场景(定时播报、连击特效、进度条)用的是同一条管线。

## 4. 建议的最小切片(D2, 待 D0 答完再定稿)
- 切片 1: **VMD 解析**(读动作时长/帧数即可, 不必解析骨骼) -> 时间轴 -> 按 30~60Hz 发 float 参数(隔离实例里断言报文频率与数值范围);
- 切片 2: 播放控制(开始/暂停/停止/循环/进度跳转) + 音频同步(可选: 本地播放音频作为节拍参考);
- 切片 3: 与触发器层联动(手势开始/停止) + 直播插件预研接口;
- 切片 4(可选): `VRCEmote`/int 选曲支持(纯外挂情形)。
