## 一、能力总览(一句话版)

    ✅ 能做:  切相机模式 · 拍照/定时拍照 · 图层与绿幕 · 透明底 8K 立绘
              · 镜头参数(变焦/曝光/光圈/焦距)· 构图偏移 · 防抖/水平锁定
              · 触发/换/停运镜(VRC+)· 飞行相机位移(仅 VR)
    ⚠️ 半自动: 跟随方式、对焦模式、对焦点 —— **无 OSC 入口, 必须手动设**
    ❌ 不能做: 读相机位姿 · 精确控制相机位置与朝向 · 读运镜播放进度
              · HSL 调色(可写但无效果)

## 四、/input(仅 VR 模式有效)

    MoveForward / MoveBackward / MoveLeft / MoveRight / LookLeft / LookRight ...(全部 bool, 写)
    PC 模式下无效(PC 飞行需按住鼠标中键)

**位移换算**(三点验证):

    前进 X 米 = 脉冲 (X / FlySpeed) 秒
    例:走 5 米, FlySpeed = 0.2 -> 25 秒;  FlySpeed = 3 -> 1.67 秒
    注意: 开环无反馈, 长距离会累积误差 -> 建议**短程多段**(每段 <= 5 秒)

## 五、三个配方(插件可直接用)

### 5.1 电影感画面

    Mode = 1(本地单张) 或 2(直播)
    对焦模式 = 半自动(SA)      [手动设, 无 OSC 入口]
    对焦点   = 点一次圈 -> 回到中心  [手动设, 无 OSC 入口]
    Aperture = 1.4             [OSC]
    LookAtMe = true            [OSC]
    AutoLevelRoll = true       [OSC]
    => 主体永远清晰居中、背景柔化、画面不歪

  原理:半自动模式的对焦点是**监视器上的一个二维坐标点**(像手机点屏幕对焦),
  没有人脸识别/运动追踪;但 LookAtMe 能让玩家的头**永远待在画面中心**,
  于是"把焦点放在中心"就等于**等效的自动跟焦**。

### 5.2 简易实时运镜(不依赖 VRC+)

    Flying = true              [OSC, 仅 VR]
    LookAtMe = true            [OSC]
    位置由 /input 脉冲控制(FlySpeed 数值 = 米/秒)
    => 环绕 / 推近 / 拉远 / 平移, 而且镜头始终盯着玩家

### 5.3 直播自动链路(事件触发)

    事件(上舰/礼物)
      -> Mode = 2(直播相机, 显示器输出相机画面 -> OBS 直接抓窗口)
      -> /dolly/Import 换一条专用轨迹
      -> /dolly/PlayDelayed 3
      -> Capture 定格一张 8K
      -> 还原 Mode

    ① 跟随方式   默认(镜头与监视器一体,像拿手机) / 玩家(自拍杆,跟着你) / 世界(三脚架,固定)

    ④ 飞行模式   若要用实时运镜(也可用 OSC 写,但实测写入不稳定,以面板为准)

## 七、避坑与纪律(都踩过)

    1. OSC 报文必须 **NUL 结尾 + 4 字节对齐**, 否则 VRChat **静默忽略**;
    2. **用 OSC 写 FlySpeed 会出怪值**(写 1 读回 15)-> 一律"写后读回确认", 不一致以读回为准;
       速度/模式这类值**优先让用户在面板上调, 插件只读**;
    3. OSCQuery 端口**每次启动都变**, 需从 output_log 里读 "type OSCQuery on <port>";
    4. 照片在 **Pictures/VRChat/<年-月>/** 下, 不在顶层;
    5. 半自动/全自动模式下 `FocalDistance` 只是**上次手动写入的残留值**, 不能用来判断当前焦点;
    6. "对准我"跟踪的是**头部**, 头部有自然微动 -> 用**人像像素位置**做测量会有噪音,
       验证这类参数时**用地平线/墙地交界当参照**更可靠;
    7. 测量前请用户**锁死参照物**(如锁定 T-pose 模型), 并且**一次只改一个变量**。

## 七点六、对焦模式补充 + 飞行模式与跟随方式的关系(2026-10-16)

### 对焦模式的四种(用户经验补充)

| 模式 | 行为 | 评价 |
| --- | --- | --- |
| 关闭 | 0~无限远全清晰(无景深) | 需要全画面锐利时用 |
| **半自动** | 自动对画面中心(焦点**可手点**改) | 用户日常首选: 选好焦点后只调光圈 |
| **手动** | 焦距 + 光圈全程可控(FocalDistance 可 OSC 精确写入) | 需要选择性对焦时用 |
| 全自动 | 点了哪里那里清晰、其他地方模糊 | 用户评价: **属于套公式, 不是很好用**, 像**傻瓜相机** -> 插件配方不推荐 |

### 飞行模式(/usercamera/Flying)是开关量, 且与跟随方式联动

1. **类型**: TYPE=T(**布尔**), OSC 侧发 **T / F** 标签 —— **不是数字**。
   因此**无法把跟随方式编码进 Flying**(用户问的是否为数字、会不会和跟随模式一起 -> 答案: **不会**);
2. **用户观察**: **开启飞行模式后, 跟随方式默认为世界**, 要手动切到玩家;
3. **推测**(待验证): 跟随方式 = 默认(镜头与监视器**一体**)时**无法飞行**,
   所以一开飞行就进入镜头与监视器**分离**的状态 -> 只能是**世界(三脚架)或玩家(自拍杆)**;
4. **对插件的含义**: **开飞行模式会改变跟随方式** —— 插件在用实时运镜前必须提示
   "飞行模式下请确认跟随方式是 世界 还是 玩家"(跟随方式无 OSC 入口, 见第六节)。

## 七点七、为什么半自动才是 VR 里的正解 + 一个插件构想(2026-10-16)

**用户原话**:

> "我经常用半自动对焦是因为: 手动模式 VR 监视器就那么一点, 根本看不清楚对好没有,
>  经常拍完了看原图发现自己成了用尼康那样 **背景如刀锋般锐利, 主体如奶油般化开**
>  (我借我同事尼康相机玩就这样, 我用单位的佳能就不会)。
>  用半自动只要调光圈搞好虚化效果就行了。"

### 结论: 半自动是 VR 环境下的正解

| 模式 | 在 VR 里的实际体验 |
| --- | --- |
| **手动** | 焦平面在画面里**看不出来**(监视器太小) -> 常常拍完回看才发现主体糊了、背景锐利 ✗ |
| **半自动** | 焦点自动落在**画面中心** -> 只要把主体放在中心就对 ✓; 只需调光圈控制虚化程度 ✓ |
| 全自动 | 用户评价"套公式、像傻瓜相机" -> 不好用 |

=> 插件配方**默认推荐半自动**(见第五节"电影感画面")。

### 由此产生一个插件构想: 手动模式的"照片闭环自动对焦"

   1. 插件用 OSC 设一个 FocalDistance -> 拍一张照片;
   2. 读回照片, 用**边缘能量/清晰度**分别评估"主体区域"与"背景区域";
   3. 若主体比背景更糊 -> 换一个 FocalDistance 再拍(扫描或二分);
   4. 找到"主体最清晰"的那个距离 -> 设为最终焦距。

=> 把"看不见焦点"的手动模式, 变成**可用的自动对焦** ✓✓
   (两个前提都已具备: **FocalDistance 可精确写入** ✓ + **照片可读可分析** ✓)
   ⚠️ 需要知道"主体在画面中的位置" —— 可用中心区域近似, 或配合已知构图/偏移设置。

**这条的价值**: 用户日常最痛的点(手动对焦在 VR 里看不见)正好可以用插件补上,
而且用料全是已经验证过的东西, 不需要任何新能力。

## 七点十、⭐⭐⭐ 重大更正:`/usercamera/Pose` **真的会发送**!(2026-10-22)

**之前的结论(§38.2)作废** ✗ —— 当时监听 8 秒收不到相机报文, 误判为"VRChat 不发姿态"。
**真实原因**: `Pose` 是**事件驱动**的 —— **相机静止时不发送, 一旦相机移动/转动就连续发**(约 40 次/秒)。

### 实测(用户先锁死滚转+俯仰, 然后顺时针绕一圈)

```
/usercamera/Pose   ,ffffff   [posX, posY(高度), posZ, rotX, rotY, rotZ]
```

| 分量 | 本次范围 | 结论 |
| --- | --- | --- |
| posX / posZ | -9.18 / 8.40 | 水平位置(世界坐标, 本次未变) |
| **posY** | 1.50 -> 1.40 | **高度**, 转一圈下降了 **0.10 m**(用户预判正确 ✓) |
| rotX | **0.00 全程** | 被锁死的轴之一 |
| ⭐ **rotY** | **0.07 ~ 359.78(跨度 359.71)** | ⭐ **偏航(yaw)** —— 完整绕一圈 ✓✓ |
| rotZ | **0.00 全程** | 被锁死的轴之一 |

时间序列可见 rotY 平滑扫过 351→95→148→199→236→277→317→**3**→56→105→154→201→251(完整一周 ✓)。

### 还要确认的一件事
本次 **rotX 与 rotZ 都被锁在 0** -> 只能确定 **rotY = 偏航**;
**rotX / rotZ 哪个是滚转、哪个是俯仰, 尚未分清**(需单独解锁一个再测)。
(注意轴序不寻常: 通常 XYZ 对应 俯仰/偏航/滚转, 而这里偏航在 **Y** ✓)

### 对插件的意义(巨大)
```
✅ 能**实时**拿到镜头的位置与三轴角度(~40Hz)-> 闭环反馈的地基成立
✅ 网页可以显示"当前角度/位置"; 照片估角那套可以退休
✅ 可以做"精确角度运镜": 读角度 -> 判误差 -> 修正
⚠️ 只在相机**运动时**有数据(静止时不发) -> 需要"最后一次已知值"缓存
```

### 7.10.1 ⭐ Pose 轴映射**全部确定**(2026-10-22 第二次实测)

**测试 2**: 用户只解锁"滚转"(俯仰仍锁), 转动镜头。2394 个采样:

| 分量 | 范围 | 结论 |
| --- | --- | --- |
| posX / posY / posZ | 全部恒定(-9.18 / **1.50** / 8.40) | ⭐ 原地转动时位置**完全不漂移** |
| rotX | 0.00 恒定 | 始终没动 |
| rotY | 357.66 恒定 | 测试1 里它扫过 0~360 -> **偏航** |
| ⭐ rotZ | **0.07 ~ 359.97(跨度 359.90)** | ⭐ 本次唯一变化的轴 -> **滚转** |

## ⭐ 最终轴映射(可写进插件)

```
/usercamera/Pose  ,ffffff  [posX, posY(高度m), posZ, rotX, rotY, rotZ]

位置: posX / posY / posZ       单位: 米(世界坐标)
旋转: rotX = 俯仰(pitch)      <- 由排除法得出(两次测试均未直接验证, 可再确认一次)
      rotY = 偏航(yaw)        <- 测试1: 水平转一圈, 该轴扫过 0~360
      rotZ = 滚转(roll)       <- 测试2: 解锁滚转并转动, 该轴扫过 0~360
```
