# 流程 5:质量门与验收清单(Quality Gate & Acceptance)

> 适用对象:接手本项目的人类开发者与 AI。**本文件是可执行清单,不是建议。**
> 配套:`PROCESS-02`(开发流程)、`PROCESS-04`(行动纪律 13 条)、`PROCESS-03`(安全审计)、`scripts/checks/` 里的门禁。
> 来历:**2026-10-05 一天之内被用户连续挑出六个问题**, 全部属于"代码写完但没用起来"同一类。本文件把那次教训固化成清单。

## 0. 一句话
> **"代码写完"不等于"功能做完"。** 验收的标准是用户的那四条, 不是我的"我觉得可以了"。

## 1. 提交前四条自查(用户视角, 每次前端/交互改动必过)
```
① 能点吗?        新增的控件有没有真的接上事件?(而不是只有外观)
② 看得出状态吗?  用户能不能一眼看出"开/关 / 已选 / 生效"?
③ 会重复吗?      刷新、轮询、重进页面之后, 会不会多出一份?
④ 重启还在吗?    设置类改动**关掉程序再打开**还在不在?
```
### 这四条是从哪来的(六个真实翻车)
| 现象 | 根因 | 对应的自查 | 现在由谁守 |
| --- | --- | --- | --- |
| 页面只剩一个标题(白屏) | `window.__dsel.get(x) = ...` 给函数调用赋值, 启动时抛 ReferenceError | ① | GBOOT 把"页面运行时错误"判为失败(**已加, 含反证**) |
| 九键数字态按 0 还是空格 | `0/1/*` 的分支写在"数字态判断"之前 | ① | 人工验收(键盘页) |
| 勾了插件保存后不显示 | 快捷开关的行是**硬编码的 8 行**, 而清单有 13 项 | ① | 人工验收 |
| 补出来的行没有开关, 也没状态 | 只 append 了名字 span, 没给 `.sw` | ① ② | 人工验收 |
| 同一项出现两行 | 补的行没有 `.sw` -> 去重选择器匹配不到 -> 每次都再补一遍 | ③ | 人工验收 |
| 设置改完重启回默认 | **服务端从来没处理过 `ui` 段**(POST 忽略、GET 不回) | ④ | **必须做一次"写入->读取"往返验证**(见 §3) |

## 2. 验收分层(能做到哪层就写清哪层, 不许含糊)
| 层级 | 例子 | 谁来做 |
| --- | --- | --- |
| **静态断言** | `dsel-defaults.js`(自绘下拉不得空心)、`pack-script-check.js`(stage 清理必须严格)、`dsel-check.js`(禁止 `__dsel.get()=` 赋值) | 门禁自动 |
| **行为断言** | `dsel-behavior.js`(26 条)、`ime-assert.js`(12 条)、`ime-stress.js`(五组压力)、GBOOT(前端能跑起来) | 门禁自动 |
| **往返验证** | 设置类功能: 写入 -> 读取 -> 比对(见 §3) | 开发时**手工跑一次** |
| **人工验收** | 桩件做不到的部分(见 §4): 动态插节点、真实渲染、VR 手感 | **必须交给用户**, 并在交付说明里点名 |

## 3. 设置类改动的强制验证(今天栽过)
```powershell
# 写入
curl.exe -s -X POST -H 'Content-Type: application/json' -d '{"ui":{"dashHide":["plg:xxx"]}}' http://127.0.0.1:19190/api/config
# 读回
curl.exe -s http://127.0.0.1:19190/api/config
```
- 两件事都要验: **POST 真的落库**(GET 能读回)+ **GET 真的返回该字段**(前端读得到);
- 只验一半 = 没验: 今天就是"前端在存、服务端没收, 服务端不返回、前端读不到", 两头都断了却看不出来;
- 更彻底的: **关掉程序再打开**, 看设置是否仍在(这是用户的原话验收标准)。

## 4. 门禁的已知盲区(写清楚, 不要假装没有)
1. **DOM 桩件的三个限制**(`scripts/checks/frontend-boot.js`): 没有 `parentNode`/`closest`; `getElementById` 只认 index.html 里的**静态 id**(动态插入的节点查不到); `setTimeout` 不触发 —— 所以"点编辑能拉出全量清单"这类行为断言**做不了**, 已在代码注释里写明并转为人工验收;
2. **语法检查查不出运行时错误**: `node --check` 全绿也可能整页白屏(GBOOT 现在能兜住运行时错误, 但兜不住"逻辑接错");
3. **打包行为**只有真打包才验得到(`make-dist`), 门禁只做静态断言 + 源码一致性比对;
4. **VR 手感**永远只能人来验(字号、会不会动、点不点得中)。

## 5. 提交纪律(今天违反过, 写死)
1. **语法不过不许提交**: 提交命令里先 `node --check`, 不通过就 `exit 1` —— 今天把红着的 `main` 推上去过一次;
2. **编辑工具报错后不要连续硬改**: 先**读回**目标区域确认现状(今天因为匹配到半截区域, 复制出一段重复代码, 导致语法错误);
3. **半成品不入库**: 只落了一半的控件(有按钮没处理器)、靠猜变量名的守卫 —— 撤掉比留着好;
4. **反证才算验过**: 断言必须证明"违规时它会失败"(本项目已用这一条证明过: 静态守卫、GBOOT 运行时错误、GPACK 源码一致性);
5. **门禁必须绿着离开**: `run-gates.ps1`(必要时 `-Smoke`、`-Pack`)。
