## 2. 用户侧 3 分钟自查

按顺序做，任一步变化都记下来：

1. **确认版本**：至少 1.4.8。旧版（≤1.3.1）的“UDP 空闲=红”是旧误报设计，不是故障。
2. **确认在世界内**：OSC 要进入世界后才稳定生效；只在登录界面/主菜单不算。
3. **确认 OSC 开关**：Action Menu → Options → OSC → Enabled；每个账号单独设置，改完重启 VRChat。
4. **退出加速器再试**：完全退出小黑盒/网游加速器/VPN，重启 VRChat，再启动软件。
   已知加速器会劫持本机 loopback，导致软件发出的 UDP 9000 到不了 VRChat（手动打字正常、软件发的不显示）。
5. **看 9000 端口**：按 Win+R 输入 `cmd`，执行：

   ```bat
   netstat -ano | findstr :9000
   ```

   正常应能看到 `UDP    0.0.0.0:9000` 或 `UDP    127.0.0.1:9000`，最后一列 PID 属于 `VRChat.exe`。
   用 `tasklist /FI "PID eq 那个PID"` 可看进程名。若不是 VRChat，把进程名一起发来。
6. **端口是否改过**：只有 VRChat 启动参数用过 `--osc=自定义端口`，或用了 OSC 路由器，才改软件端口；
   默认两边都应是 9000。改过就说明自定义值，不要按默认排查。
7. 仍不行：收集第 1 节的诊断报告和日志。

## 4. 开发者分诊表

| 诊断报告/现象 | 最可能原因 | 下一步 |
|---|---|---|
| 版本 ≤1.3.1，UDP 空闲被标红 | 旧版误报（M-20260902-06） | 要求升级 1.4.8 复测；升级后仍红才继续 |
| 顶部圆点灰 | 游戏没开/日志没更新 | 确认 VRChat 进程与世界；重启软件 |
| 顶部圆点黄 | 游戏开着但 OSC 没开 | 游戏内 Options → OSC → Enabled；重启 VRChat |
| `udpPortState = 被 VRChat 占用(正常)`，但状态仍红 | 前端状态/日志解析/显示层 | 要截图与浏览器控制台报错；核对版本是否 1.4.8 |
| `udpPortState = 被占用: 其他进程` | 9000 被占用 | 找出该进程；关闭它或让 VRChat 用默认端口；不要在冲突时改软件端口硬试 |
| `udpPortState = 空闲`，但 VRChat 在运行且已开 OSC | 未进世界 / 账号 OSC 未生效 / 日志路径读不到 | 要 output_log 最新文件，搜 `OSC enabled: True` 与 `of type OSC on`；确认启动方式与 USERPROFILE |
| 健康总览正常、手动打字能显示、软件发的不显示 | 加速器/虚拟网卡劫持 loopback（DEV-NOTES 109） | 退出加速器 + 重启 VRChat；`netstat` 看绑定是否虚拟网卡 IP |
| 自定义端口/OSC 路由器 | 两端端口不一致 | 核对 VRChat `--osc=`、路由器转发、软件「OSC 发送端口」 |
| 软件发的字到聊天框但显示乱码/截断 | 不是本问题 | 转字符长度/编码问题，另开问题 |

### 判为“可关闭/已解决”的最低证据

- 升级 1.4.8 后复测：状态卡绿色，且聊天框实际出现软件发送的文本；或
- 明确找到外部原因（加速器/端口占用/自定义端口）并复测恢复；
- 以上至少有一张状态卡截图或一段诊断报告，不能只凭口头“好了”。
