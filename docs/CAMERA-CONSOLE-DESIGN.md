# 相机控制台(局域网网页)设计草案

> 2026-10-19 用户提出。目标: 用**手机/平板**在局域网里操作 VRChat 相机的全部参数,
> 交互参考 **Pioneer DJ XDJ 系列控制器**(推子 + 打击垫 + 大圆按钮), 暗色、移动优先、手指友好。
> 示意图: [mockup-console.png](./mockup-console.png)(手机竖屏 620×1180 渲染)

## 1. 布局(自上而下)

    ┌────────────────────────────────┐
    │ ① 顶部状态条: 名称 · 局域网地址 · 延迟 · VRChat 在线 │
    ├────────────────────────────────┤
    │ ② 信息卡: 当前载入的预设运镜文件                     │
    │   文件名 / 点位·段数·位移·模式·预计时长              │
    │   右侧两个**大圆按钮**: CUE(发送数据) · PLAY(播放/暂停)│
    ├────────────────────────────────┤
    │ ③ 四个**小打击垫功能切换**: 预设运镜 · 相机模式 · 图层 · 镜头 │
    ├────────────────────────────────┤
    │ ④ **8 个大号打击垫**(2×4): 快速导入预设/快速功能      │
    │   激活: 实心高亮(或闪烁);  未激活: 彩色描边           │
    ├────────────────────────────────┤
    │ ⑤ **竖向推子区**(全部相机参数, 横向滑动看更多)        │
    │   ⭐ 每个推子的**数值显示在推子上方**(手会遮住下方)     │
    │   推子下方是参数名                                  │
    ├────────────────────────────────┤
    │ ⑥ 四个功能钮: 手动控制 · 允许 · 锁定 · 复位           │
    └────────────────────────────────┘

## 2. 颜色分组(打击垫按功能组着色, 一眼看出状态)

| 功能组 | 颜色 | 当前展示的垫子 |
| --- | --- | --- |
| 预设运镜 | 青绿 #00E5C0 | P1 环绕_01 · P2 推近_02 · P3 环绕_02 · P4 特写_01 |
| 相机模式 | 蓝 #4DA3FF | 本地单张 / 直播 / 多图层 / 拍立得 |
| 图层 | 琥珀 #FFB020 | 自己 / 其他玩家 / 场景 / UI |
| 镜头 | 紫 #B07CFF | 光圈 / 焦距 / 曝光 / 变焦 |

**激活态**: 实心高亮 + 轻微脉冲动画; **执行中**: 闪烁; **不可用**: 灰暗。

## 3. 推子清单(建议 9 个, 横向可分页)

    飞行(开关) · 飞行速度 · 转向速度 · 光圈 · 焦距 · 曝光 · 变焦 · 平滑 · 滚转水平

> 每个推子**: 上方数值 + 中间轨道 + 手柄 + 下方参数名**。
> ⚠️ 数值必须在**上方**(用户明确要求: 手会遮住推子下方的数字)。

## 4. 交互要点

    · **CUE** = 把选中的预设运镜"发送"到 VRChat(相当于 /dolly/Import)
    · **PLAY** = 播放/暂停(相当于 /dolly/Play|PlayDelayed 3)
    · 推子: **手指拖动**调值, 且**写后读回**(避免 VRChat 端出现怪值)
    · 手动控制/允许/锁定/复位: 控制"推子是否可动 / 是否被锁定 / 一键还原默认"
    · 手机友好: 大触控区(≥44px)、暗色、无滚动条、横向分页看推子

## 5. 待定的设计问题(需要用户拍板)

1. **推子数量**: 一屏 9 个偏挤 -> 是否改成"推子分页"(飞行页/镜头页/图层页)?
2. **手机方向**: 竖屏(推子多)vs 横屏(更像 DJ 台)? 建议**响应式**, 两种都给。
3. **打击垫功能组**: 4 组够不够? 是否要加"事件/自动化"组?
4. **紧急停止**: 是否加一个**全局大红按钮**(停止运镜 + 关相机 + 复位)?
5. **数值显示位置**: 竖屏放推子上方 ✓; 横屏可放推子旁边(空间更宽)。

## 6. 技术形态(初步)

    · 由 camera-path 插件**自带一个静态网页**(插件目录下), 主进程暴露只读/只写的最小接口;
    · 局域网访问: 监听 0.0.0.0 的独立端口(默认关闭, 需在插件设置里显式开启并给出口令);
    · 网页只调用**插件自己的 api**(不直连 OSC), 由插件统一做"写后读回确认";
    · 移动端: 纯原生 HTML/CSS/JS, 无框架、无构建, 便于长期维护。
